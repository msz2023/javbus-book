# JavBus Desktop

按 [需求文档.md](需求文档.md) 的需求做的桌面端影片资料库客户端：Electron + React + TypeScript + Tailwind。

## 快速开始

```bash
npm install          # 已装过可跳过
npm run dev          # 开发模式启动
npm run build        # 构建到 out/
npm start            # 运行构建产物
npm run dist         # 只构建免打包目录（dist/win-unpacked/，调试打包问题用）
npm run pack         # 打包成免安装单文件 exe（dist/JavBus Desktop <版本>.exe）
npm run verify       # 用真实请求校验解析器（列表/详情/磁力）
npm run verify:code  # 校验文件名→番号的提取规则（19 个用例）
npm run verify:bc    # 校验 BitComet 接入（解析本机任务表，可选联网打接口）
npm run verify:fill  # 校验「按番号补齐资料」：番号匹配 + 拿影片库真实番号打站点
npm run typecheck    # 类型检查
```

> **在 VS Code 内置终端启动会失败**：VS Code 会注入 `ELECTRON_RUN_AS_NODE=1`，
> Electron 会退化成纯 Node 进程并报 `Cannot read properties of undefined (reading 'requestSingleInstanceLock')`。
> 解决：`unset ELECTRON_RUN_AS_NODE && npm run dev`，或改用系统终端 / PowerShell。

## 功能对应

| 需求 | 实现 |
|---|---|
| 按每一页爬取，页数映射到桌面端 | 分页器显示的页码就是站点页码（`/page/N`、`/genre/{id}/N` 等），支持上一页/下一页/跳页与 `←` `→` 快捷键 |
| 展示影片具体内容 | 封面、片名、識別碼、發行日期、長度、導演、製作商、發行商、系列、類別、演員（带头像）、样品图（可放大浏览） |
| 提供 bt 种子 | 详情页磁力表格：名称、大小、分享日期、高清/字幕标签；可用 BitComet 下载、交给系统默认程序（迅雷等）、复制磁链 |
| 显示下载进度 | 接入 BitComet：「远程接口」模式 2 秒轮询真实进度/速度/剩余时间，支持暂停、继续、删除；「仅命令行」模式读 BitComet 的 `Downloads.xml`（速度按两次采样差分算），有落盘延迟 |
| 调用本机播放器 | `shell.openPath` 调用系统默认播放器，卡片悬停、详情页、下载页、本地文件列表都有播放入口 |
| 显示哪个下载了哪个没下载 | 扫描影片库目录，从文件名提取番号建索引，卡片上显示绿色「已下载」角标，可只看已下载/未下载。硬盘上有文件但没抓过资料的影片，进「已下载影片」页会自动按番号搜索入库（见下） |
| 按導演/類別/演員筛选 | ①站内筛选：点详情页里的任意标签直接跳到该导演/类别/演员的站点分页；②本地筛选页：对已抓取缓存做导演 ∧ 类别 ∧ 演员 ∧ 下载状态的组合筛选，带命中计数 |
| 搜索 | 顶部搜索框支持番号 / 片名 / 演员名，可切换有码（`/search`）与无码（`/uncensored/search`）范围，`/` 键快速聚焦 |
| 浏览视图 | 三种：**完整图像**（站点大封面 `pics/cover/*_b.jpg`，800×538 横版不裁切）、**小图像**（缩略图密排）、**详细信息**（一行一部的表格，带日期/标签/下载状态）。右上角切换或 `Ctrl+1/2/3`，卡片宽度和界面缩放都可调 |
| 尽量美观 | 深色 HUD 风：等宽读数 + 青色遥测色 + 细网格底纹 + 状态灯，封面网格悬停放大、骨架屏、抽屉式详情、图片灯箱、Toast 提示 |

额外做的：收藏夹、批量抓取（按页码区间把详情+磁力抓进本地缓存，供离线浏览与本地筛选）、缓存位置可自定义。

## 关键配置（设置页）

- **界面**：默认视图（完整图像 / 小图像 / 详细信息）、卡片宽度、界面缩放。缩放走 Chromium 的 `zoomFactor`，图片和边框跟着一起缩，不会只放大字号把布局挤坏。窗口默认尺寸会按工作区裁一刀——高 DPI 屏的逻辑分辨率常常只有物理的 2/3，写死大数字会让窗口跑到屏幕外。
- **网络**：代理模式（自动探测/手动/关闭）。站点在国内需要代理，「自动探测」会扫常见本机端口（7897/7890/10809/1080…）。封面图也走同一代理，并由主进程注入 `Referer`（站点图片有防盗链，缺 Referer 直接 403）。
- **请求间隔**：站点会对过快的请求返回 `429 Too Many Requests`（`Retry-After: 7~8` 秒）。实测约 **2.5 请求/秒** 是安全线，默认 420ms 间隔 + 并发 3，抓一整页（30 部详情 + 磁力）约 27 秒、零失败。遇到 429 会自动读 `Retry-After` 全局降速重试。
- **下载器（BitComet）**：三种模式，设置页随时切换。
  - **远程接口**（推荐，需 BitComet **2.18+**）：有实时进度，能暂停/继续/删除。开启方式：BitComet → 选项 → 远程下载 → 勾选启用，设好端口和密码，填回设置页点「测试连接」。地址不确定就点「自动探测」，它会扫常见端口（1235/8080/8081/9090…）。
  - **仅命令行**：零配置，等价于 `BitComet.exe /url "magnet:?..."`（磁力协议注册表关联用的那条命令）。进度改从 BitComet 定期落盘的 `Downloads.xml` 读，有几秒到几十秒延迟，也没法在下载页暂停/继续。
  - **系统默认程序**：磁力直接交给迅雷等——这类工具没有本地接口，拿不到真实进度，程序改用扫描影片库来判断是否下载完成。

  侧栏和下载页都有**「打开 BitComet」**：本机装了就唤起它的主界面（`BitComet.exe` 不带参数），远程接口指向的是局域网另一台机器时改为打开它的 WebUI。

  **BitComet 里已有的任务也会显示。** 远程接口模式下，凡是在 BitComet 里手动加的任务都会被收进下载页（标「外部添加」），照样能看进度、暂停、删除；它们从 BitComet 里消失后这里也会跟着清掉。不想要可以在设置页关掉「显示 BitComet 里的其它任务」。

  `BitComet.exe` 与 `Downloads.xml` 的路径是自动探测的（程序路径取自磁力协议的注册表关联；装了多份时挑任务表最新的那份），探测不对可以在设置页手动指定。选「远程接口」但连不上时**不会报错卡住**，会自动落到命令行那条路把任务加进去，只是拿不到实时进度。

  **保存目录必须是 BitComet「下载目录」列表里的一项。** 2.20 的添加接口对 `save_folder` 卡得很死：字段不能省（省了报 `save_folder missing`），值必须**精确等于**列表内的某个目录——列表内目录的**子目录也会被拒**（`save_folder invalid`），而这个错误在界面上只会表现为「远程接口不可用，已改用命令行」。所以设置页会把 BitComet 里可用的目录列出来供直接点选；填了列表外的目录会给出提示，点「加入 BitComet」即可把它注册进去（走 `/api/config/directories/add`，等价于在 BitComet 里手动添加一个下载目录）。留空则用 BitComet 的默认目录。

  > 远程接口官方没有文档，路径、请求体和登录加密算法是从 BitComet 自带 WebUI 前端（安装目录 `webui\webui.zip` 里的 `assets/index-*.js`）读出来的，字段名在版本间会变。协议层单独放在 `bitcomet-proto.ts`，换版本时用 `npm run verify:bc` 对着真机确认响应即可（该脚本第一段是钉死 2.20 真机样本的离线归一自检，不需要开远程下载就能跑）。
  >
  > 2.20 上踩到的三个字段坑，都在归一自检里钉住了：
  > 1. **`task_list` 的列表项根本没有 `infohash` 字段**，infohash 只藏在 `task_guid`（`bt_<40位hex>`）里。只找 `infohash`/`info_hash` 的话整张列表都匹配不上本地任务，界面上就表现为「BitComet 在下、客户端 0%」。
  > 2. **`task/summary/get` 返回里的 `task_summary` 不是任务概要**，装的是速度曲线和分片位图（`speed_list` / `downloaded_pieces`）；真正有用的是 `task`（同列表项结构）、`task_status`（细分状态、剩余时间）和 `task_detail`（infohash、保存目录）。
  > 3. **合并两份数据不能直接对象展开**，后来的 `0` / 空串会把前面的真实进度和速度清零。统一走 `mergeTask()` 逐字段取更有信息量的那个。
- **影片库**：添加存放影片的目录（可多个，递归扫描 6 层，忽略小于 50MB 的文件）。文件名番号识别覆盖 `SSIS-001` / `ssis00001` / `ABF-377 [1080p]` / `FC2-PPV-1234567` / `HEYZO-2345` / `010119-001` 等常见命名。
- **自动补齐资料**（默认开）：「已下载影片」页是拿本地元数据缓存做筛选的，所以硬盘上有文件、但从没打开过详情页的影片在那儿是**看不见**的。开启后进入该页会把这些番号找出来自动抓取入库：先直连详情页 `/{番号}`，404 再按番号搜索（先 `/search`，再 `/uncensored/search`）。页面上有进度条和「停止」，也能手动点「补齐 N 部资料」。站点上确实搜不到的番号会记进缓存里的 `unmatched`，下次自动跳过，需要时点「重试全部」。
- **缓存**：元数据缓存（`cache.json`）与封面图磁盘缓存可放到任意磁盘；改路径后已有元数据会自动迁移，封面图缓存位置在重启后生效。

## 代码结构

```
src/main/          主进程
  index.ts         窗口、生命周期、缓存目录重定向
  browser-session.ts  给 Chromium 配代理 + 注入 Referer/Cookie/UA（封面图能显示的关键）
  net.ts           站点请求：代理、镜像故障转移、全局节流与 429 冷却、重试
  scraper.ts       cheerio 解析：列表 / 分页 / 详情 / 磁力 / URL 构造
  crawler.ts       单部抓取（详情+磁力，带缓存与离线回退）、批量抓取、按番号补齐影片库资料
  bitcomet.ts      BitComet 适配：远程接口、命令行拉起、Downloads.xml 读取、本机路径探测
  bitcomet-proto.ts  BitComet 协议层（接口路径、登录加密、XML 解析），不依赖 electron 便于脚本校验
  downloads.ts     任务表、进度轮询、命令行模式与外部下载器的兜底判定
  library.ts       影片库扫描、番号提取、fs.watch 增量刷新、调用播放器
  store.ts         JSON 持久化（设置/缓存/收藏/任务），原子写入
  ipc.ts           全部 IPC 处理与本地组合筛选
src/preload/       contextBridge 暴露的类型化 API
src/renderer/      React 界面（pages/ 四个页面，components/ 卡片、详情抽屉、分页、灯箱等）
src/shared/
  types.ts         主进程与界面共用的类型
  code.ts          文件名→番号提取、番号归一化与匹配（normCode / pickByCode）
scripts/
  verify-parse.ts     解析器真实请求校验
  verify-code.ts      文件名→番号提取规则校验
  verify-bitcomet.ts  BitComet 校验：离线解析本机任务表 +（可选）联网打接口原始响应
  verify-fill.ts      按番号补齐资料的校验：番号匹配用例 + 拿影片库真实番号打站点
```

## 站点抓取的三个坑（已处理）

1. **列表页返回 301/302，但响应体就是真实页面**。跟随跳转会落到 `/doc/driver-verify` 年龄验证页，所以请求层禁用了重定向，直接用 3xx 的 body。
2. **磁力是单独的 AJAX 接口**：`/ajax/uncledatoolsbyajax.php?gid=…&uc=…&img=…`，参数在详情页的内联脚本里，且**必须带详情页 Referer**，同时 Cookie 需要 `existmag=all` 才会输出全部磁力。
3. **同一部片的番号写法不统一**：加勒比、一本道这类日期编号在站点上是 `010119_001`（下划线），本地文件名和搜索输入通常写 `010119-001`（横线）。所以元数据缓存、影片库索引、界面上的「已下载」判断统一按 `normCode()`（去掉所有分隔符）建键和比对，否则会重复入库、且硬盘上明明有文件却标不出「已下载」。

## 说明

本程序只做检索与本地调度，磁力资源由站点网友分享，请自行确认所下载内容的合法性。抓取带并发与间隔限制，请勿把请求间隔调得过小。
